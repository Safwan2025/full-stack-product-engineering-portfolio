## How I build

- Start with the user and business outcome, then define the smallest useful slice.
- Keep API contracts explicit and validate data at system boundaries.
- Prefer readable modules, observable failures and pragmatic trade-offs.
- Use tests to protect important behavior, especially permissions and business rules.
- Ship incrementally, invite feedback and improve an existing system without losing context.

## AI-assisted engineering

I use AI as an engineering accelerator, not as a replacement for engineering judgment. I value understanding the system, validating generated code, testing assumptions, and choosing simple deterministic solutions whenever they are more appropriate.
